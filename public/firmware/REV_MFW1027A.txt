REV.2.1 (December 19, 2025) BL
	- IMPLEMENTED A FIX TO THE ARCHIVE RELATED TO THE 'NO MESSAGE' RECORDS APPEARING ON UNITS
		- THERE WAS AN ISSUE WITH HOW THE SYSTEM RECOVERED WHEN A BAD ADDRESS WAS FOUND IN THE INTERNAL FLASH
	  	  WHEN FINDING THE QSPI ADDRESS DURING STARTUP. WHEN IT FOUND THAT THE FIRST RECORD WAS GOOD BUT THE SECOND COPY
          	  WAS BAD, AND THAT AN ARCHIVE RECORD DOES NOT EXIST AT THE FIRST RECORD, IT FAILED TO CORRECTLY REWRITE THE
	  	  FLASH DATA THAT WAS STORED IN RAM.
		  THIS THEN CAUSED ARCHIVE RECORDS TO BECOME OVERWRITTEN IN THE QSPI WHEN CAUSED THE 'NO MESSAGE' INDEX
		- IN THE EVENT THAT A FIRST RECORD IS GOOD, COPY IS BAD AND ARCHIVE DOES NOT EXIST, WE NOW CLEAR THE INTERNAL FLASH
	  	  AND SEARCH THE QSPI FOR THE LAST RECENT ARCHIVE MESSAGE TO FIND OUR CORRECT ADDRESS.
	- ADDED AN RTC MUTEX FOR ALL CALLENDERGETTIME() CALLS AS IT IS SUSPECTED THAT MULTIPLE CALLS TO THIS FUNCTION
	  THROUGHOUT DIFFERENT THREADS IS CAUSING THE INCORRECT TIMES TO BE DISPLAYED.
